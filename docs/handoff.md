## 3. 데이터 구조(스키마)

### 3.1 시트 레이아웃 (Q2·Q3 시트 공통, 18개 열)

| 열 | 항목 | 입력/수식 | 비고 |
|---|---|---|---|
| A | 상태 | 입력 | 미발표 / 발표완료 / 입력대기(발표됐으나 미입력) / 확인필요 |
| B | 티커 | 입력 | |
| C | 기업 | 입력 | |
| D | 섹터 | 입력 | |
| E | 발표일 | 입력 | 미국 시간 기준 날짜. 방콕은 하루 뒤일 수 있음 |
| F | 회계기간 | 입력 | 예: FQ3 2026, Q2 2026 |
| G | 통화 | 입력 | USD / KRW / EUR |
| H | 매출 (십억) | 입력 | 보고통화 기준. 원화는 1조원 = 1,000 |
| I | 매출 컨센서스 | 입력 | |
| J | 매출 서프라이즈 | 수식 | `=(H-I)/I`, H·I 중 하나라도 비면 공란 |
| K | 매출 YoY | 입력 | 소수로 저장(0.164 = 16.4%) |
| L | 영업이익 (십억) | 입력 | 은행(JPM·GS)은 영업이익 개념이 없어 공란 |
| M | 영업이익률 | 수식 | `=L/H`, 입력 없거나 H가 0이면 공란 |
| N | EPS | 입력 | 주당, 보고통화 |
| O | EPS 컨센서스 | 입력 | |
| P | EPS 서프라이즈 | 수식 | `=(N-O)/O` |
| Q | 주가반응 (발표직후) | 입력 | 미국=시간외, 한국=발표 당일 장중 기준 |
| R | 비고 / 핵심 코멘트 | 입력 | 서술형. 해석 주의사항 포함 |

시트 구성: 1행 제목, 2행 부제(업데이트 일자·단위 안내), 3행 그룹 밴드(기본정보 / 매출 / 영업이익 / EPS / 시장반응·코멘트), 4행 헤더, 5행부터 데이터. 지역 구분행(🇺🇸 🇰🇷 🇹🇼 🇳🇱)이 중간에 들어가고, 하단에 사용 안내(Legend)가 있다. 틀 고정은 D5.

### 3.2 표시 규칙

- 서프라이즈 열(J·P)과 주가반응(Q)은 양수 초록 굵게, 음수 빨강 굵게(조건부 서식).
- 입력 셀은 파란 글씨, 수식 셀은 검정 글씨. Q3 시트에서는 아직 입력 전인 칸을 노란색으로 표시하고, 입력하면 노란색을 제거한다.
- 한국 기업 행은 연두색 배경, 구분행은 연한 파란색 배경.
- 정렬: 지역(미국→한국→대만→유럽) → 섹터 → 티커 알파벳순. 발표 시점순이 아니다.

### 3.3 단위와 통화

- 매출·영업이익은 보고통화의 십억 단위. 원화는 1조원 = 1,000.
- 통화가 다르면 절대값 비교를 하지 않고 %지표(서프라이즈, YoY, 영업이익률, 주가반응)로만 비교한다.
- TSMC는 USD 기준으로 입력한다(ADR 환산).

### 5.3 데이터 품질 이슈 (웹 트래커로 옮기기 전에 정리할 것)

1. **GS 매출 컨센서스 의심:** Q2 시트에 매출 컨센 14.47로 들어 있는데 EPS 컨센(14.47)과 같은 숫자다. 매출 20.34 대비 +40.6% 서프라이즈로 계산되고 있어 입력 오류로 보인다. 확정 컨센 확인 필요.
2. **GS EPS 컨센 14.47:** 프리뷰 추정치. 확정 컨센으로 교체 권장.
3. **Apple 영업이익 35.7:** 매출총이익 - 영업비용으로 역산한 비공식 추정치. IR 확정치와 대조 필요.
4. **ASML EPS €7.59·영업이익률 37.1%:** 2차 매체 보도이며 매출 수치와 불일치해서 시트에는 입력하지 않았다. IR 자료 대조 필요.
5. **TSMC 영업이익:** 영업이익률 60.3%는 2차 자료이고 절대액을 못 구해 공란.
6. **삼성전자·SK하이닉스 EPS:** 미공개/미확인으로 공란(삼성전자 확정 시 DART 공시 대조).
7. **삼성전자 Q3 컨센서스 정정:** 이전에 적어 둔 영업이익 컨센 110.6~111.8조는 오차였다. WiseReport(10/4) 평균은 108.1조(매출 201.7조), LSEG 106.1조, FnGuide 105.2조. 실제 107.4조는 WiseReport 대비 -0.7%, LSEG·FnGuide 대비로는 상회.
8. **MU Q3 입력 선택:** 영업이익은 GAAP $43.75B(80.7%)를 입력(회사 준비발언의 $44.6B·82.3%는 GAAP/비GAAP 표기 불명). EPS는 Q2 시트와 같은 비GAAP $33.42(GAAP $32.87). EPS 컨센은 $31.16(Investing.com 기준, 다른 집계는 $31.82), 매출 컨센은 $51.51B(Yahoo Finance).
9. **주가반응 공란:** MU Q3(시간외 보도가 +1.3%와 -0.8%로 엇갈림, 익일 종가 미확인), 삼성전자 Q3(당일 "2%대 하락" 보도만 있고 정확한 종가 등락률 미확인).
10. **Q2 시트 기준일:** Q2 시트의 비고·legend는 2026-08 기준(마지막 업데이트 2026-08-27)으로 작성돼 있다.

## 6. 웹 기반 트래커 개발 시 참고

이 장은 지금까지의 사용 방식에서 도출한 제안이며, 확정된 사양이 아니다. 개발 시작 전에 6.4의 결정 사항부터 정리하는 것을 권한다.

### 6.1 왜 웹으로 옮기나

현재 방식은 숫자·비고를 사람이 시트에 직접 쓰는 구조다. 이 때문에 (1) 출처·기준일이 셀 안의 문장에만 남고, (2) 한 기업의 여러 분기를 비교하기 어렵고, (3) 일정·확실도·검증 상태를 필터로 걸러 볼 수 없다. 웹으로 옮기면 이 세 가지를 데이터 필드로 다룰 수 있다.

### 6.2 제안하는 데이터 모델

핵심 엔티티:

- **Company:** ticker, name, sector, region, currency, fiscal_year_end, 회계기간 표기 규칙(예: MU FQ4 = 6~9월), 노출 순서.
- **Period(분기):** company, fiscal_label(FQ4 2026), calendar_window(시작~종료), 시즌 라벨(Q3 2026 시즌).
- **EarningsEvent(발표 이벤트):** period, 발표일시(UTC 저장, 미국/방콕 표시 병행), 일정 확실도(confirmed / verified / estimated), 발표 시점(장 전 / 장 후).
- **Result(결과):** event, 단계(preliminary / final — 한국 기업의 잠정·확정), revenue, revenue_consensus, revenue_yoy, operating_income, eps, eps_consensus, eps_basis(GAAP / non-GAAP), operating_income_basis, price_reaction, reaction_basis(시간외 / 장중 / 종가), notes.
- **SourceNote:** result 필드 단위로 출처 URL·집계기관(예: 컨센서스가 Yahoo인지 FnGuide인지)·기준일.
- **Flag:** 필드 단위 상태 — verified / unverified / derived(역산) / disputed(출처 간 불일치). 5.3의 이슈들이 이 구조로 바로 들어간다.

계산 필드(저장하지 않고 코드에서 계산): 매출 서프라이즈, EPS 서프라이즈, 영업이익률. 시트와 같은 규칙(입력이 하나라도 비면 계산하지 않음, 분모 0 방지)을 그대로 쓴다.

별도 테이블 후보:

- **GuidanceItem:** 하이퍼스케일러 CapEx, 분기 가이던스(매출·EPS·총이익률) 등 회사가 낸 전망. 다음 분기 실제치와 자동 대조해 "가이던스 대비 결과"를 볼 수 있다. 지금은 비고 문장에만 있다.
- **AccountingAdjustment:** EPS 왜곡 요인(지분평가이익, 회계처리 변경 등)과 조정 전후 값.

### 6.3 필요 기능(우선순위 제안)

1. **분기 선택 보기:** 지금의 한 장짜리 비교표(지역→섹터 정렬, 구분행) 그대로 + 분기 탭 전환.
2. **데이터 입력/수정 화면:** 상태, 수치, 비고 입력. 입력 즉시 서프라이즈·이익률 자동 계산. 입력 전 칸 강조.
3. **통화·단위 처리:** 원 단위 저장 후 화면에서 십억/조원 표시 선택. 통화가 다른 기업끼리는 % 지표만 정렬·비교 가능하게 제한.
4. **일정 캘린더:** 발표 예정일, 확실도, 방콕 시간 병행. 오늘 기준 "다음 발표" 표시.
5. **출처·검증 표시:** 값 옆에 출처 툴팁, unverified·disputed 배지.
6. **기업별 시계열:** 같은 기업의 분기별 매출·영업이익률·서프라이즈 추이. 시즌 간 비교(Q2 대 Q3).
7. **조건부 서식:** 서프라이즈·주가반응 양수/음수 색.
8. **내보내기:** CSV/엑셀(현재 방식과의 호환), 시트 사본 보관.
9. **분석 메모:** 비고를 마크다운으로 저장(현재 비고가 길어 가독성이 떨어짐).

### 6.4 개발 전에 정해야 할 사항

- **데이터 저장소:** 저장소 안 JSON/SQLite로 시작할지, 호스팅 DB를 쓸지. 혼자 쓰는 도구라면 파일 기반으로 시작해도 충분하다.
- **데이터 입력 흐름:** 지금처럼 "Claude에게 실적 반영을 지시"하는 방식을 유지할지(예: Claude Code가 데이터 파일을 수정), 웹 화면에서 직접 입력할지, 둘 다 쓸지.
- **구글 시트의 역할:** 웹 버전이 안정되면 시트를 읽기 전용 백업으로 둘지, 병행 입력할지. 이관 시점의 기준 데이터는 구글 시트('Q2 2026', 'Q3 2026').
- **배포·접근:** 로컬 실행인지, 호스팅해서 어디서든 접속하는지, 인증이 필요한지(투자 관련 개인 자료).
- **자동화 범위:** 컨센서스·실적 수치를 외부 API나 크롤링으로 가져올지, 계속 수동(리서치 후 입력)으로 갈지. 지금까지는 웹 검색 후 사람이 확인하는 방식이었고, 출처 간 불일치가 자주 나와서 완전 자동화는 신중해야 한다.
- **기술 스택:** 사용자가 R/RStudio에 익숙하다는 점을 감안해 R Shiny도 선택지가 될 수 있다. 다만 웹 서비스 형태로 개발할 계획이면 프런트엔드(예: React/Next.js)와 API 구성이 일반적이므로, 유지보수 부담을 보고 결정한다.

## 7. 업데이트 작업 규칙 (현재 방식, 웹으로 옮겨도 유지할 것)

1. **발표 직후 순서:** 공식 자료(IR 자료·실적발표 자료·공시) → 신뢰할 만한 보도로 컨센서스 확인 → 수치 입력 → 상태를 '발표완료'로 변경 → 비고 정리 → 입력 결과 재확인.
2. **출처가 갈리면 고르지 않고 기록:** 컨센서스는 집계기관·기준일에 따라 다르다. 선택한 값과 다른 값의 범위를 비고에 남긴다(예: MU EPS 컨센 $31.16, 다른 집계 $31.82).
3. **확인 못 한 값은 추정으로 채우지 않는다:** 공란으로 두고 비고에 사유를 적는다(삼성전자·MU 주가반응이 그 사례).
4. **회계 왜곡 분리:** EPS 서프라이즈가 지분평가이익 같은 비영업 요인에 좌우되면 영업이익·영업이익률로 본질을 판단하고, 비고에 요인을 명시한다.
5. **주가반응 해석 주의:** 같은 날 시장 전체가 급락했으면(예: 2026-07-29 KOSPI) 실적 때문인지 단정하지 않고 비고에 쓴다.
6. **한국 기업 2단계:** 잠정치를 먼저 입력하고, 확정치가 나오면 같은 행을 갱신하며 비고에 단계를 표기한다.
7. **통화가 다른 기업은 % 지표로만 비교한다.**
8. **회계연도 어긋남 표기:** MU(FQ4=6~9월), NVDA(FQ3 FY27=8~10월), AAPL(FQ4=7~9월), MSFT(FY27 Q1=7~9월)는 역년 분기와 다르므로 YoY·QoQ 비교 시 비고에 기간을 적는다.
