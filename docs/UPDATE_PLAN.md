# 주기적 업데이트 구상

2026-10-12 작성. 구글 시트를 거치지 않고 `data/*.json`을 직접, 주기적으로 갱신하는 방법.

## 무엇을 자동화할 수 있나

| 항목 | 자동화 | 이유 |
|---|---|---|
| 발표일이 지났는데 미입력인 회사 찾기 | **완전 자동** | 데이터만 보면 된다 (`validate.py`가 이미 경고) |
| 주가반응 | **자동 가능 (기준 변경 필요)** | 종가는 무료로 안정적으로 받을 수 있지만, 지금 기준인 '미국 시간외'는 무료 자료가 없고 보도마다 다르다(MU Q3 공란 사례) |
| 실적 수치(매출·영업이익·EPS) | **반자동** | 미국은 SEC EDGAR(무료, 키 불필요), 한국은 DART OpenAPI(무료, 키 필요)로 교차검증 가능. 대만·네덜란드는 공시 형식이 달라 어렵다. 발표 직후 보도자료 시점에는 정형 데이터가 없는 경우가 많다 |
| 컨센서스 | **자동화 어려움** | 무료로 믿을 만한 API가 없고 집계기관마다 값이 다르다. 리서치 후 출처를 남기는 지금 방식이 맞다 |
| 비고·해석, 번역 | **AI 작업** | 사람 수준의 판단이 필요 — Claude가 맡는다 |
| 다음 발표 일정·확실도 | **AI 작업** | 회사 IR 캘린더·8-K 확인이 필요 |

그래서 두 층으로 나눈다.

## A. Claude 루틴 (정기 실행되는 Claude Code 세션) — 핵심

클라우드에서 정해진 시각에 Claude Code 세션이 새로 시작돼 아래를 하고 끝난다. 사람이 지시할 필요가 없다.

1. `data/` 확인: 발표일이 지났는데 `scheduled`인 이벤트, 잠정 → 확정이 남은 한국 기업, 7일 안에 발표 예정인데 `estimated`인 일정
2. 해당 회사의 공식 자료(IR·8-K·DART)와 컨센서스(보도)를 찾아 `CLAUDE.md` 절차대로 반영 — 못 찾은 값은 `null` + 사유
3. 일정 갱신(확정 공지가 나왔으면 `certainty` 올리기)
4. 영어·태국어 번역 갱신
5. 검증·테스트 통과 시 커밋·푸시 → 자동 배포
6. 할 일이 없으면 아무것도 바꾸지 않고 끝

**실행 시각 제안 (방콕 기준)** — 발표가 몰리는 시각 직후로 맞춘다.

| 실행 | 잡히는 발표 |
|---|---|
| 매일 08:50 | 미국 장 마감 후 발표(방콕 03~05시), 한국 잠정실적 공시(방콕 06~07시) |
| 매일 20:50 | 미국 장 시작 전 발표(방콕 18~20시: 은행 등), 대만(TSMC 방콕 13시경)·유럽(ASML 방콕 12시경), 한국 확정실적 |

마이크론(9·12·3·6월)·엔비디아(11·2·5·8월)는 다른 회사와 어긋난 달에 발표하므로 "비시즌"이 뚜렷하지 않다. 할 일이 없는 날은 확인만 하고 바로 끝나므로 매일 돌려도 되고, 발표가 드문 기간에는 하루 1회로 줄여도 된다. 루틴은 언제든 끄고 켤 수 있다.

**결과를 반영하는 방식 (선택)**

- **바로 반영(권장):** 루틴이 `main`에 직접 푸시. 검증을 통과해야만 배포되므로 형식 오류는 사이트에 나가지 않는다. 내용 오류는 사이트에서 보고 "고쳐줘"로 정정.
- **확인 후 반영:** 루틴이 PR을 만들고, 사용자가 GitHub에서 확인 후 병합. 더 안전하지만 사용자가 매번 눌러야 한다.

**비용:** 실행마다 Claude 사용량을 쓴다. 할 일이 없는 날은 확인만 하고 끝나므로 적고, 빅테크 발표일처럼 여러 회사를 반영하는 날은 많다.

## B. GitHub Actions (AI 없이 도는 자동 작업) — 보조

`.github/workflows/`에 정기 작업을 추가한다. 무료(공개 저장소).

1. **미입력 알림:** 매일 발표일이 지난 미입력 회사가 있으면 GitHub 이슈를 연다 → 알림 메일. 루틴이 실패했을 때의 안전망.
2. **주가반응 자동 수집 (기준 결정 필요):** 발표 후 첫 거래일 종가 ÷ 직전 거래일 종가 − 1을 Yahoo Finance 종가로 계산해 `basis: close`로 넣는다.
   - 장점: 모든 회사에 같은 기준, 자동, 재현 가능. 지금 공란인 6건도 채울 수 있다.
   - 단점: 지금까지의 '미국 시간외 / 한국 장중' 기준과 숫자가 다르다(예: GOOGL 시간외 −2%, 익일 −7%).
   - 제안: 기준을 '첫 거래일 종가'로 통일하고, 시간외 반응은 보도로 확인되면 비고에 적는다. Q2 기존 값은 그대로 두고 `basis`로 구분.
3. **공시 교차검증 (나중에):** SEC EDGAR의 분기 실적(XBRL)을 받아 입력값과 다르면 이슈. 한국은 DART API 키를 GitHub Secrets에 넣으면 같은 방식으로 가능.
